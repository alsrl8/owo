# OWO 감정 스펙트럼과 입력 파라미터

## 근거와 제품 가설

[Russell의 원 논문](https://doi.org/10.1037/h0077714)은 감정을 **쾌·불쾌(valence)**와 **각성도(arousal)**의 연속 공간으로 다룬다. [Geneva Emotion Wheel](https://www.unige.ch/cisa/gew)은 **쾌·불쾌**와 **통제감(control/power)**을 사용해 감정 계열과 강도를 표현한다. 두 틀은 감정 UI의 좌표계로 참고할 수 있다. 특정 사람이 어떤 행동에 어떻게 반응할지 계산하는 공식은 아니다.

OWO의 초안은 다음 네 값을 내부 좌표로 둔다. 수치 범위와 감정별 위치는 **제품 설계 가설**이며, 사용자 검증 전까지 확률처럼 표시하지 않는다.

| 값 | 범위 | 화면에서 구별할 반응 |
| --- | --- | --- |
| 정서 방향 `valence` | -1 ~ +1 | 반가움 ↔ 불편함 |
| 각성도 `arousal` | 0 ~ 1 | 차분함 ↔ 들뜸·긴장 |
| 통제감 `control` | 0 ~ 1 | 당황·막막함 ↔ 상황을 다룰 여유 |
| 접근 의향 `approach` | 0 ~ 1 | 거리 두기 ↔ 대화를 이어가기 |

마지막 `approach`는 심리학의 공인된 감정 축으로 주장하지 않는다. OWO의 관계 시나리오에서 표정과 다음 행동을 분리하기 위한 제품 변수다.

## 우선 대응할 반응

| 반응 계열 | 좌표의 대략적 방향 | 현재 스프라이트 | 표현할 때의 구분 |
| --- | --- | --- | --- |
| 편안함·반가움 | 긍정, 낮거나 중간 각성 | smile | 가벼운 안부에 부드럽게 반응 |
| 즐거움·들뜸 | 긍정, 높은 각성 | laugh, excited | 긍정적 반응의 강도 |
| 수줍음 | 긍정 또는 미정, 높은 각성, 낮은 통제감 | shy | 호감으로 단정하지 않기 |
| 호기심 | 중립 또는 긍정, 중간 각성, 높은 접근 의향 | curious | 더 묻거나 알아보려는 반응 |
| 놀람 | 방향 미정, 높은 각성 | surprised | 뒤따르는 반응을 별도로 보기 |
| 생각 중·망설임 | 중립, 낮거나 중간 각성 | thinking, uncertain | 즉시 호감·거절로 해석하지 않기 |
| 긴장·당황 | 중립 또는 부정, 높은 각성, 낮은 통제감 | nervous | 부담과 구별할 여지 |
| 불편함·짜증 | 부정, 중간 또는 높은 각성 | uncomfortable, annoyed | 명시적인 경계 신호에 우선 반응 |
| 서운함·슬픔 | 부정, 낮거나 중간 각성 | sad, crying | 감정 강도와 원인은 별개 |
| 중립 | 중립, 낮은 각성 | idle | 정보 부족 시 기본값 |

`wave`와 `turn-away`는 감정보다 **몸짓·행동**이다. 감정 계열 위에 별도 레이어로 얹는다. 현 PoC의 `warm / neutral / overwhelmed` 세 결과는 이 세분화의 임시 묶음이다. `shy`나 `surprised`를 곧바로 `warm`으로 넣으면 뜻이 왜곡될 수 있다.

## 입력에서 좌표로 가는 방법

1. **관찰된 사실과 해석을 분리한다.** “먼저 연락했다”는 관찰, “나를 좋아한다”는 해석이다. 후자를 근거로 재입력하지 않는다.
2. **직접 상호작용을 우선한다.** 이전 경험과 최근 대화의 명시적 반응은 관계 맥락의 주요 단서다. 인스타 게시물은 여러 해석이 가능하므로 낮은 신뢰도의 보조 단서로만 둔다.
3. **현재 여유와 행동의 강도를 함께 본다.** 같은 커피 제안도 바쁜 날과 여유 있는 날의 부담이 다르다. `bandwidth`와 행동별 강도를 `arousal/control` 후보값에 연결한다.
4. **명시적 거절·경계는 별도로 취급한다.** 일반 점수의 가감보다 먼저 고려할 관찰이다. 표정 애니메이션이 이를 희석하면 안 된다.
5. **근거 부족을 수치에 숨기지 않는다.** 입력이 비었거나 게시물밖에 없으면 결과보다 불확실성을 크게 보여 준다.

| 입력 | 연결 후보 | 신뢰도 원칙 |
| --- | --- | --- |
| 현재 상태 | 각성도, 통제감 | 상대가 직접 말한 상태와 사용자의 추정 구분 |
| 이전 경험 | 정서 방향, 접근 의향 | 반복된 직접 반응에 상대적으로 높은 비중 |
| 최근 대화 | 정서 방향, 접근 의향 | 표현 자체와 시점을 함께 기록 |
| 최근 인스타 등 게시물 | 현재 상태의 약한 단서 | 특정 게시물이 나를 향한 신호라고 추론하지 않기 |
| 행동 종류 | 압박 정도, 필요한 통제감 | 안부 < 커피 제안 < 고백 같은 고정 서열도 맥락에 따라 조정 |
| 기존 슬라이더 | 초기값 | 사용자의 판단을 명시적으로 수집하되 객관적 측정값으로 취급하지 않기 |

## MBTI의 역할

[McCrae와 Costa의 연구](https://scholars.duke.edu/publication/1458465)는 MBTI가 질적으로 다른 16개 유형을 측정한다는 근거를 찾지 못했다. [MBTI 제공사 설명](https://www.themyersbriggs.com/en-US/Explore-Solutions/MBTI)도 유형이 행동 예측 척도는 아니라고 밝힌다. 따라서 `INFP → 수줍음 +20%`처럼 감정 확률에 직접 가산하는 규칙은 두지 않는다.

활용한다면 **선택적 대화 스타일 힌트**가 적당하다. 당사자가 직접 알려 준 유형일 때만 받고, 사용자가 “천천히 답하는 편”, “즉흥적인 제안을 좋아함”처럼 실제 관찰로 수정할 수 있게 한다. 예컨대 E/I는 답변의 표현성, J/P는 일정 제안의 선호를 탐색하는 가설로만 둘 수 있다. T/F로 배려심이나 호감도를 계산하지 않는다. 가산치 실험을 한다면 명시적으로 켜는 기능으로 두고, 확률 변화의 상한을 작게 정한 뒤 실제 사용자 평가로 보정해야 한다. **현재 PoC에는 MBTI 가산치가 없다.**

## 현재 구현 범위

화면은 `현재 상태 / 이전 경험 / 최근 대화·인스타에서 본 것 / MBTI`를 별도로 입력받는다. 데모 계산은 **행동과 세 슬라이더만** 사용한다. Jev 연결 시 입력한 맥락과 MBTI를 TypeSafe API로 전달하며, 직접 경험을 게시물 관찰보다 우선하고 MBTI를 약한 성향 힌트로 다루도록 질문한다. 감정 좌표와 세분화된 반응은 설계안이며, 현재 아바타는 기존 세 결과를 사용한다.
